# Ports: third-party userspace + toolchain

Sources are **not vendored** — this keeps the repo small enough for GitHub
and Codeberg (no hundred-megabyte tarballs or build trees in git).

- **Submodules** (exact pins in `../.gitmodules`):
  `pixman` (freedesktop GitLab), `oksh` (ibara/oksh @ oksh-7.9),
  `sbase` (suckless), `tcc` (TinyCC mirror).
- **Fetched tarballs** (URL + sha256 pinned in the port Makefiles):
  `gnu/` → binutils from ftp.gnu.org, `e2fsck/` → e2fsprogs from
  kernel.org. `make fetch` downloads, verifies and unpacks them.

First checkout (fresh clone):

    git submodule update --init   # or: make -C ports fetch (also tarballs)
    make libs                     # mlibc + ports, as usual

What lives in this repo per port (wrappers only):

- `Makefile` — all build/install/uninstall recipes.
- `rbos-cc` — cross-compiler wrapper used by every port.
- `pixman-cross.txt` — meson cross file for pixman.
- `patches/oksh/` — rbOS nocurses fallback (`cur_term` stubs), applied
  on top of upstream oksh-7.9 (upstream has no curses in mlibc).
- `oksh-config/` — snapshot of oksh `configure` output (Makefile +
  pconfig.h). Re-running configure detects different features and the
  generated Makefile was hand-trimmed for the port, so the snapshot is
  copied instead of re-configuring.
- `tcc-config/` — saved `config.h`/`config.mak` from the working rbOS
  tcc build. `configure` is not re-run (it probes the host); the rbos
  target values are reused verbatim. Re-validate if upstream `tcc`
  sources change the config surface.
- `gnu/patches/`, `e2fsck/patches/` — rbOS patches for the tarball
  ports (libiberty getopt dedup; e2fsck syscall/shim guards).
- `e2fsck/` extras: `build` (fetch + configure + manual static link),
  `rbos-cc-wrap.sh`, `sbrk_shim.c`.

Rebuilding from scratch is always safe: build trees (`gnu/build`,
`pixman/build-rbos`, `e2fsck/b`) and unpacked tarball sources are
regenerated by `make fetch` / `make setup`.

## OpenBSD-compatible declarations

rbOS keeps the Linux ABI as its primary contract. OpenBSD compatibility is
opt-in and currently covers the standard-header placement of:

- `pledge(2)` in `<unistd.h>`;
- `arc4random`, `arc4random_buf`, `arc4random_uniform` in `<stdlib.h>`;
- `unveil(2)` in `<unistd.h>` (the kernel implements the `pledge`/`unveil`
  syscalls and enforces the unveil policy on VFS path walks).

The compiler wrapper `ports/rbos-cc` always defines `__rbos__=1`. The port
framework (`ports/Makefile`) exports `RBOS_OPENBSD_COMPAT=1`, which makes
`rbos-cc` add `-D__RBOS_OPENBSD_COMPAT__=1`; that enables `pledge` in
`<unistd.h>`. `arc4random*` are also visible with `_DEFAULT_SOURCE`, matching
glibc. Build through `make -C ports` (or export the variable yourself when
invoking a port sub-make directly).

Ordinary programs built with `user/rbos-cc` do not get `pledge` in their
namespace. A source that guards OpenBSD code with `#ifdef __OpenBSD__` still
needs a port-specific `-D__OpenBSD__` in its Makefile; rbOS does not define
`__OpenBSD__` globally and does not emulate the whole OpenBSD ABI.

The two include hooks in mlibc's public `unistd.h`/`stdlib.h` are not a fork.
They live in `../mlibc-sysdeps/patches/` and are applied idempotently by
`../tools/patch-mlibc-headers.sh` from both mlibc build scripts and
`../tools/populate-sysroot.sh`. If upstream mlibc changes the anchor, the
patch fails the build instead of silently dropping the declarations.
